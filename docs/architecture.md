# 架构

## 顶层模型

`borderless` 是 2-3 台同一局域网内的桌面设备组成的对等网格。
每个节点在线协议上完全对称；唯一动态的角色是当下握有物理输入的"主动节点（Active）"
和正在接收转发事件的"被动节点（Passive）"。这样我们就避开了
Synergy 那种"server 一挂全停"的单点故障。

每对节点之间共享一条 QUIC 连接，承载两条逻辑通道：

```
                   ┌──────────────────────────────────────┐
                   │             控制平面                  │
                   │   （mDNS 发现、配对、拓扑下发）        │
                   └──────────────────────────────────────┘
                                     │
                                     ▼
        ┌──────────────────────┐         ┌──────────────────────┐
        │     输入通道         │         │     剪贴板通道        │
        │ QUIC 数据报（移动）   │         │ QUIC 流 + 大对象懒拉   │
        │ QUIC 流（按键）      │         │                      │
        └──────────────────────┘         └──────────────────────┘
                                     │
                                     ▼
                 ┌────────────────────────────────────────┐
                 │   平台抽象层（`pal`）                   │
                 │   capture / emit / clipboard / cursor  │
                 └────────────────────────────────────────┘
```

## 设计不变量

- **鼠标移动走不可靠 QUIC 数据报**，受限于单个 MTU；偶尔丢一帧
人类是无感的。按键、剪贴板和控制消息走可靠流。
- **鼠标位移以 `(dx, dy)` delta 形式发送**，不传绝对坐标。
这样跨 DPI / 跨分辨率不需要做坐标系换算。
- **修饰键状态随 `Enter` 帧一起到达**。光标越过逻辑屏幕边界时，
目标节点先按发送方上报的"当前按住的修饰键"重放一遍，
避免"按住 Shift 越界后下一个键被脏掉"的情况。
- **剪贴板快照携带 `origin` 与 Lamport `version`**。
收到来自自己的快照，或版本号小于等于本地已发布版本的快照，一律丢弃。
这条规则消灭了朴素同步工具常见的 A↔B 回声死循环。
- **大于 256 KiB 的剪贴板项只发元数据**。接收端在真的执行"粘贴"时，
根据 BLAKE3 哈希开一条新 QUIC 流去拉取实际内容；
这样复制 500 MB 视频不会阻塞整张网。

## 威胁模型（v0.1）

仅限局域网。我们假设的攻击者是同一 Wi-Fi 上的被动监听者。
**不**在威胁模型范围内：已经通过 SAS 配对的恶意 peer、国家级攻击者、侧信道攻击。

缓解措施：

- QUIC 强制 TLS 1.3，节点身份用自签 Ed25519 长期密钥。
- Short Authentication String（SAS）：双方各自显示同一个 6 位数字，
从 TLS 导出的 keying material 派生而来；用户口头/即时通讯比对一致。
- 配对成功后将对端 Ed25519 公钥指纹固化到 `known_peers.toml`（TOFU）。
之后再次连接时指纹不一致即拒绝。
